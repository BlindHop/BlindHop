# TX Validity Proof — Well-Formed Extrinsic

The **TX Validity Proof** proves that the extrinsic being submitted is well-formed — without revealing its contents to the exit node before submission.

## Circuit Specification

| Aspect | Detail |
|---|---|
| **System** | Stwo Circle STARK (M31 field) |
| **Constraints** | ~15,000 AIR constraints |
| **Proving time** | ~2,000 ms (Wasm), ~200 ms (native) |
| **Proof size** | ~4 KB |
| **Generated by** | Light client (in browser Wasm) |

## What It Proves

This is a **simplified** proof — it does NOT hide transaction contents (that's Phase 4). It proves:

1. **Valid SCALE encoding** — the extrinsic follows Substrate's SCALE codec format
2. **Correct nonce range** — the nonce is within a valid range for the sending account
3. **Valid signature format** — the signature bytes are well-formed (sr25519/ed25519/ecdsa)
4. **Correct call index** — the pallet + call indices reference a valid dispatch

## Public Inputs

| Input | Description |
|---|---|
| `extrinsic_hash` | Blake3 commitment to the full extrinsic |

## Private Inputs

| Input | Description |
|---|---|
| `extrinsic_bytes` | The complete signed extrinsic |
| `scale_structure` | Parsed SCALE structure witnesses |

## Why Simplified?

Full content hiding requires significantly more complex circuits that handle account state transitions, balance proofs, and commitment schemes. This is deferred to **Phase 4**, where BlindHop provides a pluggable adapter layer for integrating value-privacy mechanisms.

The simplified TX validity proof is intentionally minimal so it can run in **browser Wasm** in under 3 seconds — critical for user experience.
